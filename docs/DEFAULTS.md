# Решения по умолчанию и разрешённые расхождения (`docs/DEFAULTS.md`)

Единый реестр архитектурных решений по умолчанию (`DEC-04`, Приложение C `MASTER_PROMPT.md`) и
разрешённых противоречий исходного диалога `razrabotka_orkestra.html` (`§1.2`, `C-01…C-15`).
Любой пункт может быть пересмотрен заказчиком через новый ADR или конфигурацию `.env`.

---

## 1. Решения, принятые по умолчанию (`D-01…D-19`)

| ID | Тема | Принятое решение | Обоснование / Где реализовано |
|---|---|---|---|
| **D-01** | Хранилище состояния | JSON-снапшот `mental_map.json` + append-only `events.jsonl` (без внешней СУБД) | Нулевая инфраструктура при старте, прозрачная отладка, детерминированный replay (`ADR-0003`) |
| **D-02** | Пакетный менеджер | `uv` с автоматическим фолбэком на `pip` + точные пины в `requirements*.txt` | Быстрое воспроизводимое разрешение зависимостей (`ADR-0002`, `Makefile`) |
| **D-03** | Фронтенд Web-дашборда | **Зафиксировано заказчиком:** Vanilla JS + локальный Cytoscape.js в `orchestra/web/vendor/`, без Node.js и шага сборки | Мгновенный запуск, 100% offline-работа, сохранение чистого REST/WS контракта (`ADR-0007`) |
| **D-04** | Режим песочницы | `subprocess` с лимитами ОС по умолчанию; `docker` — опцией конфигурации | Быстрый локальный старт на Windows/Linux без обязательного Docker; мягкая деградация (`WIN-20`, `ADR-0005`) |
| **D-05** | Хэширование паролей в целевых проектах | Рекомендация `Argon2id`, но при отсутствии в ТЗ **обязательно эскалируется человеку** | Компромисс CPU vs стойкость — бизнес/инфраструктурный выбор заказчика (`§26.5`, `BE-03`) |
| **D-06** | СУБД целевых проектов | PostgreSQL + SQLAlchemy 2.x (async) + Alembic; Redis для кэша/очередей | Промышленный стандарт асинхронного Python-бэкенда (`§26.5`, `BE-04`) |
| **D-07** | Доступ агентов в сеть | Отключён по умолчанию (`sandbox.network=disabled`); `allowlist` — только для `research` | Безопасность выполнения недоверенного кода и детерминизм тестов (`SB-04`, `SEC-04`) |
| **D-08** | Аренда ключей в пуле | `exclusive_lease=False`, `max_concurrent_per_key=2` + token-bucket на каждый ключ | Равномерный расход бесплатных лимитов без простоя параллельных ветвей (`KP-02`, `KP-04`) |
| **D-09** | Языковая политика | Код, логи, ADR и межагентный RPC — английский (ASCII); SITREP и RUNBOOK — русский | Минимум BPE-расхода и галлюцинаций внутри роя + точность общения с заказчиком (`ADR-0006`) |
| **D-10** | Лицензия | Не фиксируется (оставлена на усмотрение владельца репозитория) | Не влияет на исполнение кода |
| **D-11** | Первый целевой проект | База для работы с криптобиржами и создания алгоритмических стратегий | Прямое указание заказчика (`Часть VIII`, `ADR-0008`) |
| **D-12** | Режим торговли по умолчанию | Строго `PAPER`; `LIVE` заблокирован до прохождения чек-листа и ручного подтверждения человека | Защита капитала (`TR-07`, `DP-06`, `DP-71`, правило `LIVE_MODE_GUARD`) |
| **D-13** | Клиент криптобирж | **Зафиксировано заказчиком:** мультибиржевость с 1-го дня, baseline `ccxt` + нативные адаптеры точечно | Набор бирж будет расширяться без правки ядра (`§38.19`, `DP-78…DP-88`, `ADR-0008`) |
| **D-14** | Демо-стратегия | Учебная стратегия (пересечение SMA / наблюдение funding) с явным дисклеймером `NOT INVESTMENT ADVICE` | Проверка сквозного конвейера без инвестиционных обещаний (`DP-66`, `DP-72`) |
| **D-15** | Секреты бирж в `LIVE` | OS `keyring` или зашифрованный vault-файл (выбор эскалируется человеку); `.env` — только `PAPER`/`TESTNET` | Защита боевых API-ключей (`DP-29`, `DP-69`) |
| **D-16** | Основная платформа | **Зафиксировано заказчиком:** Windows — первичная ОС, Linux/macOS — вторичные (CI, контейнеры) | Платформенный слой `§13.21` (`WIN-01…WIN-23`, `ADR-0004`) |
| **D-17** | Docker на Windows | Docker Desktop + WSL2 с трансляцией путей `to_container_path`; без Docker — деградация в `subprocess` | Отказоустойчивость старта на ПК без поднятого Docker (`WIN-18…WIN-20`) |
| **D-18** | Активные биржи при старте | `exchanges.enabled = []` (пусто, fail-closed) в `exchanges.yaml` и `Settings` | Ни одно подключение к реальной бирже не открывается без явного включения (`DP-88`) |
| **D-19** | P2P-рынок | Вне объёма первого проекта, но `p2p` заложен в `ExchangeCapabilities.markets` для будущего `DomainExtension` | Сохранение расширяемости без раздувания первой поставки (`DP-87`) |

## 2. Сводка разрешённых противоречий `razrabotka_orkestra.html` (`C-01…C-15`)

При сверке `razrabotka_orkestra.html` с `prompts/MASTER_PROMPT.md` v1.2.1 зафиксированы следующие
окончательные правила (ранние тезисы из диалога отменены):

- **C-01 (Рой):** динамический состав `2..20` агентов от декомпозиции задачи вместо фиксированной пятёрки.
- **C-02 (Модели):** провайдер-агностичный слой `LLMProvider` + `capability probe` вместо хардкода `GLM` или `Nemotron`.
- **C-03 (Генерация):** `temperature=0.0` (или `min_temperature` провайдера) + `seed=1337` вместо `temperature=1.0`.
- **C-04 (Интерфейс):** resident-ядро FastAPI + 3 тонких клиента (Web, Telegram, CLI) вместо одиночного CLI-скрипта.
- **C-05 (Атомы кода):** единый лимит `MAX_CHUNK_LINES = 300` (рекомендуемо `200`).
- **C-06 (Ключи):** пул ключей с временной арендой (`lease/release`), token-bucket и cooldown на `429`/`5xx`.
- **C-07 (Язык):** `EN_TELEGRAPHIC` (ASCII) внутри JSON-RPC, русский `SITREP` — только человеку от Архитектора.
- **C-08 (Промпты):** трёхслойный контекст-бюджет `20% Persona / 30% Sub-Map / 50% Skills Index` (скиллы — только по ID).
- **C-09 (Дневники):** статус `VERIFIED` в `DISCOVERY_DIARY` — строго через 4-шаговый `Empirical Proof Gate`.
- **C-10 (Мутация скиллов):** правка общих скиллов — строго через `Skill Mutation Gate` (100% старых + новый тест + совместимость JSON Schema).
- **C-11 (Персистенция):** атомарный JSON-снапшот + `events.jsonl` + single-writer actor + optimistic concurrency.
- **C-12 (Споры):** запрет горизонтальных дебатов; максимум 1 раунд уточнения контракта → `DISAGREEMENT_TICKET` Архитектору; `MAX_RETRIES = 2`.
- **C-13 (Приёмка):** первичен детерминированный судья (`exit code 0`), LLM-ревью — только поверх зелёной машины.
- **C-14 (Claude Code):** нулевая зависимость от внешнего кода; собственная реализация паттернов (`PatchEngine`, атомарный git, перехват вывода).
- **C-15 (Фреймворк):** собственный рантайм на `asyncio` + Pydantic v2; `langgraph`/`langchain`/`autogen`/`crewai` запрещены (`ADR-0001`).

## 3. Технические уточнения ревизии ТЗ `v1.2.1` (`ADR-0009`)

1. Корень репозитория `./` является корнем проекта `ORCHESTRA` (`./pyproject.toml`, `./orchestra/`, `./tests/`).
2. Исходные аналитические материалы (`prompts/MASTER_PROMPT.md`, `prompts/SOURCE_ANALYSIS.md`, санитизированный `razrabotka_orkestra.html`) сохранены в репозитории; шаблоны системных промптов размещены в `orchestra/prompts/templates/`.
3. Порог покрытия ядра `≥ 85%` (`M-03`, `TT-05`) применяется к пакетам `state`, `verify`, `inference`, `swarm`, `agents`, `comms`.
