# ADR-0002: Grounded Dependency Baseline from PyPI Index

- **ID:** ADR-0002
- **Date:** 2026-10-30
- **Status:** Accepted (`§34.1`, `AH-04`, `D-02`)

## Context

Per `AH-04` and `§34.1`, package versions must never be guessed from training memory. All runtime
and development dependencies must be queried live against the PyPI JSON API and jointly resolved
against Python `>=3.11` using `uv` (`0.13.6`).

## Decision

Pin the exact resolved versions verified against `https://pypi.org/pypi/<pkg>/json` on `2026-10-30`
in `requirements.txt` and `requirements-dev.txt`, while declaring compatible major-bounded ranges
in `pyproject.toml`:

- Runtime: `openai==3.41.0`, `pydantic==2.13.5` (jointly compatible with `aiogram==3.31.0`),
  `pydantic-settings==2.16.2`, `httpx==0.28.1`, `fastapi==0.162.0`, `uvicorn[standard]==0.54.0`,
  `aiogram==3.31.0`, `rich==15.0.0`, `typer==0.27.3`, `structlog==26.1.0`, `pyyaml==6.0.3`,
  `tiktoken==0.14.0`, `websockets==17.4`.
- Dev & Judge toolchain: `ruff==0.17.3`, `mypy==2.4.1`, `pytest==9.2.0`, `pytest-asyncio==1.4.1`,
  `pytest-cov==7.1.0`, `hypothesis==6.170.14`, `respx==0.23.1`, `types-PyYAML==6.0.12.20261030`.

## Rationale

Live resolution caught an upstream upper-bound constraint in `aiogram==3.31.0` requiring
`pydantic<2.14` (`pydantic==2.13.5` instead of standalone latest `2.14.2`), preventing installation
conflicts out of the box.

## Alternatives Considered

- Unpinned floating ranges in `requirements.txt`: rejected because unpinned environments break
  deterministic judge reproducibility.
- Heavy git wrapper libraries (`GitPython`): rejected per `§34.1` in favor of async `git` CLI via
  `asyncio.create_subprocess_exec`.

## Consequences

- Reproducible environment installation via `make install` (`uv` primary, `pip` fallback).
- Target projects generated by ORCHESTRA maintain their own isolated virtual environments (`SB-09`).
