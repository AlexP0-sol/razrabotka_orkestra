# razrabotka_orkestra

Проектирование и задание на реализацию **ORCHESTRA** — автономной фабрики разработки ПО
с динамическим эволюционирующим роем LLM-агентов.

**Первый целевой проект фабрики:** база для работы с криптобиржами и создания
алгоритмических торговых стратегий (Часть VIII мастер-промпта).

## Содержимое репозитория

| Файл | Что это |
|---|---|
| `razrabotka_orkestra.html` | Исходник: сохранённая страница архитектурного диалога в Arena.ai (Source of Context) |
| `prompts/MASTER_PROMPT.md` | **Главный результат.** Исчерпывающий мастер-промпт / ТЗ для ИИ-агента, который реализует оркестратор. 547 формализованных требований, 15 фаз поставки (P0…P13), схемы данных, мета-промпты, Definition of Done из 44 пунктов, доменный пакет крипто-трейдинга |
| `prompts/SOURCE_ANALYSIS.md` | Анализ исходного диалога: хронология 12 реплик, карта покрытия «идея → раздел промпта», список того, что добавлено сверх обсуждения |

## ⚠️ Безопасность: утечка ключа

В `razrabotka_orkestra.html` в открытом виде лежит **реальный API-ключ NVIDIA Build** (`nvapi-…`),
а репозиторий **публичный**.

1. **Отозвать и выпустить новый ключ** в кабинете NVIDIA Build — он скомпрометирован.
2. Вычистить ключ из HTML (замена на `nvapi-REDACTED`).
3. Секрет остался в истории git (коммит `048c9d8`). После отзыва ключа история не опасна;
   если нужна полная очистка — `git filter-repo` или пересоздание репозитория.

## Как применить мастер-промпт

**Основной режим (зафиксирован): кодинг-агент с доступом к этому репозиторию.**
Достаточно отправить агенту:

```
Прочитай prompts/MASTER_PROMPT.md целиком и выполни его как техническое задание.
Начни с фазы P0. Работай по фазовому протоколу §4, пиши файлы прямо в репозиторий,
запускай проверки и коммить каждую завершённую фазу (FP-09…FP-15).
razrabotka_orkestra.html — вторичный источник контекста;
все расхождения разрешай по таблице §1.2.
```

Агент обязан вести `docs/PROGRESS.md` (статус фаз P0…P13) — это точка возобновления
работы после любого прерывания.

**Резервный режим — чат-модель без инструментов.** Скопировать весь текст
`prompts/MASTER_PROMPT.md` в первое сообщение, приложить `razrabotka_orkestra.html`,
далее на каждом ходе отправлять `Продолжай. Фаза P<N>.` — модель выдаёт файлы целиком
и завершает фазу маркером `[[PHASE_PN_COMPLETE]]`.

**Подача по частям** (если контекст исполнителя ограничен). Минимально достаточный набор:

## Ключевые решения системы

- **Язык:** внутри машины — телеграфный технический английский (ASCII, JSON-RPC);
  наружу человеку — русский в формате SITREP при `temperature = 0`.
- **Рой:** состав агентов не захардкожен — Архитектор проектирует команду под задачу (2…20).
- **Состояние:** ментальная карта — единственный источник истины; DAG, ADR в узлах,
  реестр антипаттернов, атомарная персистенция, восстановление после краха.
- **Верификация:** детерминированный судья `ast.parse → ruff → mypy --strict → pytest`,
  exit code 0 важнее мнения модели; атомы кода ≤ 300 строк; TDD; Skeleton First + заморозка контрактов.
- **Эволюция:** профессии (`/agent_talents/`) и скиллы (`/skills/`) живут между проектами;
  запись опыта — только через Empirical Proof Gate; мутация скилла — только через TDD-гейт.
- **Человек:** неблокирующая эскалация в Telegram — ждёт только затронутый узел, рой работает дальше.
- **Провайдер:** адаптерный слой + capability probe, NVIDIA Build по умолчанию;
  модель — конфигурация, а не константа.
- **Стек оркестратора:** Python ≥ 3.11, чистый `asyncio` + Pydantic v2
  (без LangGraph/AutoGen/CrewAI), FastAPI + WebSocket, aiogram 3.x, Rich.
- **Крипто-домен:** `Decimal` вместо `float` для денег, UTC везде, идемпотентность ордеров
  через `clientOrderId`, состояние `UNKNOWN` при обрыве связи, ресинк стакана после реконнекта,
  pre-trade risk-шлюз и kill switch, режим по умолчанию `PAPER`, `LIVE` — только после явного
  подтверждения человека.
